# ADR-0018 — Darwin release binaries are ad-hoc code-signed with rcodesign

- **Status:** Accepted
- **Date:** 2026-09-14
## Context

kindboard's darwin release binaries (built per ADR-0017, cross-compiled from
this Linux box via osxcross) ship **unsigned**. Verified against
`dist/x86_64-apple-darwin/kindboard`: no `LC_CODE_SIGNATURE` load command at
all; arm64 carries only the linker placeholder (`CS_LINKER_SIGNED`), which
Gatekeeper treats as unsigned.

When a user downloads a tarball, macOS applies the `com.apple.quarantine`
xattr; **unsigned + quarantine = "kindboard is damaged and can't be opened"**,
and right-click → Open does **not** bypass that combination (the bypass only
works for "unidentified developer", which requires *some* signature).

The toolchain gap: osxcross ships `codesign_allocate` but **no `codesign`
wrapper**, so there is no signing step in the current pipeline. User
constraints (unchanged from ADR-0017): **no Apple Developer account, no
Xcode — pure Rust toolchain only**, builds stay local/Makefile-driven.

## Decision

Ad-hoc code-sign every darwin binary in `scripts/build.sh` with
**rcodesign** — the CLI binary of the pure-Rust `apple-codesign` crate
(`cargo install apple-codesign --locked`; works on Linux, signs Mach-O from
an ELF host, and works natively on macOS).

- After the binary is copied into `dist/<target>/`, before tarballing:
  `rcodesign sign` (ad-hoc, no identity) then signature verification on the
  **dist/ copy** (cargo's `target/` output stays pristine).
- **Signature verification is host-aware.** On macOS the canonical
  `codesign --verify --strict` runs. On Linux, `rcodesign verify` proved
  unusable for ad-hoc signatures (it demands CMS data ad-hoc signatures
  don't have: "CMS error: missing further values" → "problems reported
  during verification"; the tool itself prints a warning that `verify` is
  buggy). The Linux gate is therefore structural via `verify_darwin_signature`:
  an `LC_CODE_SIGNATURE` load command **and** the `CSMAGIC_EMBEDDED`
  (`fade0cc0`) magic at its `dataoff`. Independently confirmed for both
  arches that the blob contains `CodeDirectory` + `Requirements` records.
- **Hard fail** if rcodesign is missing: the target is marked
  `FAILED: rcodesign not found …` and **not tarballed** — never ship unsigned
  darwin assets. Signing is *not* skippable, unlike the graceful
  osxcross/SDK-linux-linker skips.
- Applies to both cross builds (osxcross) and native macOS builds — same
  loop path.
- An ad-hoc signature + quarantine downgrades Gatekeeper to "unidentified
  developer", which the user bypasses once via right-click → Open (or
  `xattr -d com.apple.quarantine`).

## Alternatives considered (rejected)

- **Apple Developer ID + notarization** — the "proper" fix; rejected: paid
  account, key management, and violates the user's pure-Rust/no-account
  constraint.
- **ldid** — the classic ad-hoc signer; rejected: C++ toolchain and packaging
  friction on Fedora 44 vs. a `cargo install`.
- **Ship unsigned** — rejected: that is the reported bug.
- **Ad-hoc sign via rcodesign** — CHOSEN: pure Rust, one cargo install,
  satisfies "no Apple Developer account, no Xcode".

## Consequences

- Gatekeeper still blocks first launch, but downgrades to **"unidentified
  developer"** — bypassable once (right-click → Open, or
  `xattr -d com.apple.quarantine ./kindboard`). This is a UX footnote, not
  the "damaged" hard error. Documented in README.
- The Linux build host gains one new dependency: `cargo install
  apple-codesign --locked` (rcodesign on `PATH`, overridable via
  `KINDBOARD_RCODESIGN`).
- `scripts/build.sh` grows a darwin signing step + hard-fail branch; missing
  rcodesign fails the target (and therefore `KINDBOARD_REQUIRE_DARWIN=1`
  builds and `make dist-macos`), so the release pipeline can no longer
  silently produce broken macOS assets.
- No entitlements, no notarization claims — nothing here implies "verified
  developer"; the signature is purely a Gatekeeper classifier.

## Verification

- `rcodesign sign` exits 0 for both darwin targets; blob magic
  `CSMAGIC_EMBEDDED` at `LC_CODE_SIGNATURE.dataoff` (od/xxd check).
- `llvm-objdump --macho --private-headers dist/<target>/kindboard` shows an
  `LC_CODE_SIGNATURE` load command on **both** arches (x86_64 previously had
  none).
- `scripts/build.sh` with rcodesign missing marks darwin targets FAILED,
  removes any stale tarball for that target, and produces no darwin
  tarballs; with rcodesign present, both darwin tarballs are produced and
  `SHA256SUMS` covers them.
- `rcodesign verify` is intentionally **not** used as the gate (see Decision);
  `print-signature-info` is used for manual inspection only.
- macOS smoke test (no Mac hardware here; deferred to a user machine):
  extract tarball, right-click → Open once, app launches with no "damaged"
  error.
