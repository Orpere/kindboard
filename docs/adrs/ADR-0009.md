# ADR-0009 — Subprocess policy

- **Status:** Accepted
- **Date:** 2026-09-12

## Context

kindboard shells out to 6+ CLIs. Shell interpolation, unbounded output, zombie children, and un-cancellable long commands are the classic ways this kind of tool misbehaves and leaks processes.

## Decision

All subprocess invocation goes through one `exec` module with these rules:

1. **`tokio::process::Command`**, never `std::process`, never `sh -c`, never string-built command lines. **Args arrays only** — `Command::new(prog).args(&[...])`. On Unix, `.process_group(0)` (std's safe `setpgid(0,0)` equivalent via `posix_spawn`) so a Ctrl-C/kill can reap the whole tree. (Updated 2026-09-12: the originally-planned `pre_exec` new-session trick is dropped — it is unsafe with threaded runtimes and the process group alone satisfies the reap-the-tree requirement.)
2. **No shell interpolation.** Paths, cluster names, image names, and CIDRs are passed as separate argv entries; user input containing spaces/metachars is inert.
3. **Streaming, bounded output.** stdout/stderr are consumed by tasks feeding the `Event` stream (progress/log lines). stderr is capped at a 2 KiB tail kept for error messages. No `output()` on unbounded streams. stdout is decoded **lossy per line** (chunk read → split on `\n` → per-line UTF-8 lossy conversion): an invalid byte becomes U+FFFD in that line only, never silently ends the stream (2026-09-12 review fix — `BufReader::lines()` truncates a `docker logs` stream at the first binary byte).
4. **Timeouts on every call.** Default 5 m for `kind create`, 2 m for helm/cilium, 30 s for version probes; override per `KindCommand` variant. Timeout → `SIGTERM` → grace 5 s → `SIGKILL` → `Error::Timeout`.
5. **Cancellation** via `tokio_util::sync::CancellationToken`; cancel → same TERM→KILL ladder → `Error::Cancelled`. Cooperative, no orphan children. A spawned-but-never-waited `ProcessHandle` kills its process group with SIGKILL on drop (drop cannot await the TERM grace), so task aborts and worker shutdown can never leak a subprocess; `wait`'s terminal paths mark the child reaped first so the drop guard never signals a reused pgid.
6. **Env is inherited, intentionally (amended 2026-09-12).** The child inherits the full environment; `Cmd::env` only *adds or overrides* specific variables. The originally-planned sanitized allow-list was rejected in the security audit: kind/kubectl/docker/helm legitimately read `KUBECONFIG`, `DOCKER_HOST`, `DOCKER_CONTEXT`, `HELM_*`, `HTTP(S)_PROXY`/`NO_PROXY`, `KUBECACHEDIR`, and other user configuration from the environment — an allow-list would break real user setups. User input remains argv-inert per rule 1 (no shell, args arrays only), so the environment is not an injection channel. The one sensitive *data* channel — subprocess stdout reaching progress events — is guarded at the event boundary: every line forwarded to `ProvisionEvent`/`InstallEvent` is scrubbed of kubeconfig secrets (client-key-data, client-certificate-data, token, password) by `exec::redact_kubeconfig_secrets`.
7. **Exit code 0 is the only success.** Non-zero → `Error::Command { prog, code, stderr_tail }`.

Consequences (accepted):

- Higher boilerplate per command; mitigated by encoding every invocation as a `KindCommand` enum variant (contracts.md §2) so args are built once and reviewed.
- On Windows `CommandExt` differs — **out of scope** (targets are Linux + macOS only per product requirements).
- `SIGTERM`→`SIGKILL` ladder adds ~5 s worst-case latency to cancellation; accepted in exchange for no zombie/leak guarantee.

Verification: `exec` has integration tests that spawn a `sleep`-like helper, assert timeout kills the *child*, not the parent, and that cancellation reaps the process group.
