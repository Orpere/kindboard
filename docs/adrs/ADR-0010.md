# ADR-0010 — kube-rs vs kubectl-JSON for cluster reads

- **Status:** Accepted
- **Date:** 2026-09-12
- **Supersedes:** ADR-0007 (which pinned kube-rs for topology; this ADR scopes *where* each mechanism is used)

## Context

kindboard needs to (a) read live cluster state (nodes, workloads, pods, services, ingresses, events) for the topology, and (b) occasionally apply manifests (CNI/ingress). Two mechanisms exist: the kube-rs Rust client, or shelling out to `kubectl -o json` and parsing.

## Decision

**Use kube-rs (`kube` 4.x) as the primary read path**, with `kubectl`-JSON only as a narrow fallback.

- Reads that drive the topology use `kube::Client` + `Api<T>` + `kube::runtime::watcher` (typed, streaming, cancellation via `CancellationToken`).
- The kube-rs client is built from the same `~/.kube/config` the app edits; this guarantees the app reads *exactly* what it writes (single source of truth).
- `kubectl` remains in use only for: (1) `apply -f <manifest>` (kubectl's server-side/client-side apply is more robust than reimplementing apply semantics), (2) one-off `kubectl wait`, (3) log tailing where `kubectl logs -f` is simpler than kube-rs log streaming, and (4) user-visible "open a shell/kubectl" affordances.

Trade-off table:

| Mechanism | typed/safe | streaming/watch | apply manifests | log follow | cost |
|---|---|---|---|---|---|
| kube-rs | high (typed, deserialized) | yes (watcher) | no (would reimplement apply) | partial (raw stream) | adds `kube` dep |
| kubectl -o json | low (hand-rolled serde structs, drift risk) | poll only | yes | yes | requires kubectl installed |

Consequences (accepted):

- `kubectl` remains a hard runtime dependency for apply/logs even though reads are kube-rs; this is already required by the product (dependency panel installs kubectl).
- kube-rs pulls in `tower`/`hyper`/`rustls`; acceptable for a desktop tool (not a size-constrained binary).
- The topology model is *ours* (`TopologyGraph`), not kube-rs's raw objects; kube-rs objects are mapped at the boundary so core's types stay stable.

Verification: kube-rs 4.2.0 is the current crate (`cargo search kube`); `Kubeconfig` API confirmed in `kube-client/src/config/file_config.rs`.
