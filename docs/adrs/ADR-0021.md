# ADR-0021 — Security audit (2026-09-14): Windows sha256 gate + hardening

- **Status:** Accepted
- **Date:** 2026-09-14

## Context

Full-repo security audit (OWASP / supply-chain / malicious-code review) after the
cross-platform color fix. **No intentional malicious code found** — no backdoors,
no obfuscation, no unexpected network endpoints (all hosts in `github.com`,
`raw.githubusercontent.com`, `api.github.com`, `get.helm.sh`, `dl.k8s.io`,
`kind.sigs.k8s.io`, official CLI domains, `127.0.0.1` for kubeconfig),
no hardcoded credentials, no `curl | sh`, no eval of remote content.

One **High** and four **Low** findings were fixed; a `cargo audit` advisory
(medium) was fixed by dependency upgrade.

## Findings and fixes

### H1 — Windows sha256 verification gate never fired (High, fixed)

`deps/mod.rs` verified downloads only when `step.program == "curl"`, but the Windows
plan's download step runs `curl.exe` — the sha256-pinned artifact was **executed
without verification** on Windows (the Unix path verified correctly).

**Fix:** the gate matches the curl family case-insensitively
(`"curl"` | `"curl.exe"` — Windows program names are case-insensitive) and remains
anchored to the `-o` target resolving to a `DownloadVerify` entry.
**Regression test:** `every_download_step_is_sha256_verified_on_all_platforms`
walks every tool × {linux, macOS, windows} plan and asserts each curl-family step
has exactly one non-empty sha256 verify entry for its `-o` file.

### L2 — Symlink-following file writes (Low, fixed)

`fsutil.rs` used `File::create` for the atomic-write temp file and
`std::fs::copy` for the `.bak` backup — both follow a pre-planted symlink, letting a
local attacker redirect kubeconfig writes/exfiltration through `<target>.bak`.

**Fix:** `create_new_temp` opens sibling temps with `create_new` (O_EXCL, never
follows symlinks, 16 retries on collision); `backup` copies through an O_EXCL temp
then renames over `.bak` (rename replaces a planted symlink instead of writing
through it) and copies source permissions so a `0600` kubeconfig never gains a
world-readable backup.
**Regression tests:** `backup_replaces_a_planted_symlink_instead_of_writing_through_it`
(unix) + existing `private_write_creates_0600`.

### L3 — Kubeconfig secret redaction gaps (Low, fixed)

Redaction only matched `key: value` at line start on stdout progress lines;
`stderr_tail` embedded in `ExecError` reached UI errors unredacted, and YAML's
`key : value` (whitespace before the colon) passed through.

**Fix:** `redact_kubeconfig_secrets` now allows whitespace between key and colon
(and no longer redacts longer keys sharing a prefix, e.g. `tokens:`);
`tail_for_error` — the single funnel for stderr tails into `ExecError` — redacts
**per line**.
**Regression tests:** `redact_handles_whitespace_before_colon_and_key_prefixes`,
`error_tail_scrubs_kubeconfig_secrets`.

### L4 — Non-HTTPS kubeconfig server URLs (Low, fixed)

`KubeconfigStore::ensure_context` accepted any URL scheme; a crafted context could
persist `http://` / `file://` servers into the user's kubeconfig.

**Fix:** only `https://` servers are accepted (`InvalidServer` otherwise).
**Regression test:** `ensure_context_rejects_non_https_servers` (4 schemes, nothing
merged).

### L5 — World-readable log files (Low, fixed)

`--log-file` / detach log was created with default umask (0644); logs can contain
exec argv and environment detail.

**Fix:** the log file is chmod `0600` on unix right after open.

### M1 — rustls advisory (Medium, fixed)

`cargo audit`: RUSTSEC-2026-0285 (TLS 1.3 handshake messages accepted across
encryption level boundaries, rustls < 0.23.45, pulled via `kube` rustls-tls).
**Fix:** `cargo update -p rustls` → 0.23.45. Audit now reports **0 vulnerabilities**
(503 dependencies).

### Info (accepted / documented)

- **I1:** installer scripts fetch `SHA256SUMS` from the same release rather than a
  locally pinned copy — standard release trust model; `KINDBOARD_VERSION` pinning is
  the documented mitigation.
- **I2:** Windows `taskkill /T` has a narrow PID-reuse race, honestly documented in
  code; call sites gate on `reaped`. Tolerable for a user-scoped tool.
- **I3:** `log::debug!` prints full argv; current invocations are secret-free.
  Maintain that invariant (redaction exists for stderr/stdout content).
- **I4:** `$KUBECONFIG` / `$TERMINAL` / `KINDBOARD_*` env knobs are same-user
  controlled — no privilege boundary.

### Supply-chain hygiene

`Cargo.lock` was gitignored; for a binary application the lock must be committed
(pinned, reproducible builds). **Fix:** removed from `.gitignore`; the lockfile is
now a tracked artifact to audit.

## Verification

- `cargo audit`: 0 advisories (503 deps).
- Workspace tests: 56 app + 21 + 2 + 211 core + 4 e2e — all green; two full
  re-runs for determinism (0 flaky failures).
- `cargo clippy --workspace --all-targets -- -D warnings`: clean; `cargo fmt`: clean.
- `scripts/check-targets.sh`: windows-gnu check + clippy OK; darwin x86_64/aarch64
  checks OK.
- Headless screenshot smoke: all three themes render with pixel-exact palettes.

## Consequences

- Windows dependency installs are now integrity-gated exactly like Unix.
- Secrets handling is hardened against local symlink attacks and redaction gaps.
- Lockfile is tracked; supply chain is auditable per release.
