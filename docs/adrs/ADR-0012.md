# ADR-0012 — Log watching design

- **Status:** Accepted
- **Date:** 2026-09-12

## Context

The per-cluster tab shows live logs. Two backends exist: `docker logs -f <container>` (kind node containers — gets kubelet/containerd/CNI logs) and `kubectl logs -f <pod> [-c container]` (workload logs). Naive streaming into the UI would grow memory unboundedly and block the UI thread.

## Decision

- **Bounded ring buffers** (`logs::LogRing`, fixed capacity e.g. 2000 lines / 256 KiB, configurable). Oldest lines evict. The UI renders only the buffer; it never holds the full stream.
- **Follow mode** is the default: the tail of the ring is appended live; "pause" stops appending but keeps the buffer. No infinite scroll history beyond the ring (YAGNI for a local-dev tool).
- **Source selection** is explicit per cluster view:
  - `DockerLogs { container }` → `docker logs --follow <container>` for node-level logs (kubelet, CNI, apiserver). Container names are resolved from `docker ps --filter name=<cluster>-`.
  - `KubectlLogs { pod, ns, container }` → `kubectl --context <c> logs -f <pod> [-c <container>] [-n <ns>]` for workload logs, selected from the topology diagram (click a pod).
- **Streaming** is a background tokio task per open log view; each line is parsed (split on `\n`) and pushed as `Event::LogLine { cluster, source, line }` into the ring. The egui side drains events and repaints on each batch (coalesced, max ~10 Hz repaint to avoid spamming the event loop).
- **Ring persistence** (optional, off by default): the ring can be flushed to `logs/<name>/<source>.ring` on cluster tab close, so reopening restores the last N lines without re-streaming.
- **Bounded fan-out:** max concurrent log streams = 1 per open tab; closing a tab cancels its task (ADR-0009 cancellation ladder). A stuck `docker logs` child is killed by the same TERM→KILL ladder.

Consequences (accepted):

- History is capped at the ring size; users who need deep history use `kind export logs` (built by the app worker via core `exec::Cmd` directly — there is no dedicated `KindCommand::ExportLogs` variant).
- Two backends mean two slightly different line formats; `logs` normalizes to `{ timestamp?: , line }` where timestamp is best-effort (docker `--timestamps`, kubectl default).
- No search/filter in v1 (ring is small; OS-level find is enough).

Verification: unit test the ring (eviction order, capacity invariant) and an integration test that streams a bounded producer and asserts memory stays flat.
