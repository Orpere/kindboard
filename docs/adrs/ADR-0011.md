# ADR-0011 — State reconciliation model

- **Status:** Accepted
- **Date:** 2026-09-12

## Context

kindboard manages clusters, but clusters can also be created/removed *outside* the app (adopted clusters). The app must show a truthful cluster list, never blindly trust its own spec store, and act as a safety net for kubeconfig contexts.

## Decision

`kind get clusters` is the **source of truth** for "what exists"; the app's per-cluster spec store is the source of truth for "how this cluster was *created*".

- On start and on every poll tick (default **5 s**, configurable in settings):
  1. Run `kind get clusters`.
  2. For each name in the list: if we have a stored `ClusterSpec`, mark it **Managed**; if not, mark it **Adopted** (no spec, no recreate button — only destroy/export/kubeconfig-verify).
  3. For each stored spec whose name is *not* in the list: mark **Missing/Drifted** (spec exists, cluster gone) — show it greyed with a "recreate" affordance, do not auto-recreate.
- **Drift handling:** when a Managed cluster's live properties (node count, CNI, image version) differ from its stored spec, surface `Error::Drift` in the UI ("detected 3 workers, spec says 2 — reconcile?"). The app never silently mutates a live cluster; reconciliation is user-initiated (recreate).
- **kubeconfig safety net:** on start, verify every context for a Managed/Adopted cluster exists in `~/.kube/config`; if a context is missing, offer to re-merge via `kind get kubeconfig`. On `kind delete cluster`, kind already removes the context (verified) — the app verifies post-delete and repairs if a stale context lingers (using `kube::config::Kubeconfig`, ADR-0007).
- Polling uses kube-rs `watcher` for *live* topology (event-driven, no timer for the graph itself); the `kind get clusters` reconciliation tick is a cheap CLI call, not a k8s API round-trip.

Consequences (accepted):

- A 5 s CLI call per tick is negligible for local clusters (sub-100 ms each); if it ever grows, batch into a single tick per N clusters.
- "Adopted" clusters have reduced features (no spec, no scale/recreate) — this is a deliberate scope cut, not a bug.
- No background mutation: every reconcile action is user-confirmed, preserving the "safety net, not autopilot" contract.

Verification: unit tests feed a fake `KindGetClusters` output + fake spec store and assert the Managed/Adopted/Missing classification matrix.

## Amendment (2026-09-12, post-implementation)

Implementation deviates from two points above; both are deliberate scope cuts, not bugs:

- **No background reconciliation tick.** `kind get clusters` + reconcile runs on app startup, after each lifecycle event (create/recreate/destroy), and on manual refresh — not on a 5 s timer. The stored `poll_interval_secs` setting is reserved for a future tick (do not read it yet).
- **No kube-rs watcher for topology.** The per-cluster diagram is refreshed on demand and by an opt-in per-tab auto-refresh (5/10/30 s, `SetAutoRefresh`), each refresh a full snapshot via `kind get nodes`/kube-rs reads — not an event-driven watch.

Everything else holds: `kind get clusters` remains the truth for existence, drift is surfaced (never auto-mutated), and the kubeconfig safety net verifies on startup and post-delete.
