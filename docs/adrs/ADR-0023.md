# ADR-0023 — k9s always opens in the OS-default terminal

- **Status:** Accepted
- **Date:** 2026-09-15

## Context

`worker.rs::open_k9s` resolved a terminal emulator with `detect_terminal()`:
the `$TERMINAL` environment variable, then a hardcoded Linux-oriented candidate
list (`foot`, `kitty`, `alacritty`, `konsole`, `gnome-terminal`, `xterm`,
`x-terminal-emulator`).

User report: **on macOS k9s cannot find a terminal** — none of those emulators
exist on stock macOS, so the app answered "no terminal emulator found". Same
gap on Windows (kindboard ships Windows since v0.1.7).

Requirement: k9s must **always** open in the default terminal, whatever the OS.

## Decision

Keep the existing resolution order and append an **OS-default fallback**:

1. `$TERMINAL` (user override, unchanged).
2. Known emulators on `PATH` (unchanged — works on every OS when present).
3. OS-default terminal:
   - **macOS** — `osascript` drives Terminal.app (the OS default terminal):
     `tell application "Terminal" to do script "k9s --context <ctx>"` +
     `tell application "Terminal" to activate`. `open -a Terminal` cannot
     carry a command, which is why AppleScript is used.
   - **Windows** — `cmd /C start "" k9s --context <ctx>`: `start` opens the
     OS default console host (Windows Terminal / conhost) in a new window.
     The empty first argument is the window title (prevents `start` from
     consuming the next quoted argument as a title).
4. Any other OS keeps the existing explicit error.

### Quoting (no injection)

- The context is sh-quoted for the Terminal shell: always single-quoted,
  `'` → `'\''` (`sh_single_quote`).
- The resulting string is AppleScript-escaped for the double-quoted
  `osascript` literal: `\` → `\\`, then `"` → `\"`
  (`applescript_string_escape`). `osascript` receives the script as an
  `argv` element (never through a shell), so there is no shell layer between
  kindboard and AppleScript.
- Windows: the context is wrapped in `"` when it contains whitespace or
  quotes, with `"` → `\"` (`windows_quote`) — the CommandLineToArgvW
  convention k9s re-parses with.

The argv builders (`macos_default_argv`, `windows_default_argv`,
`sh_single_quote`, `applescript_string_escape`, `windows_quote`) are pure
functions, **not** cfg-gated, so they are unit-tested on every host; only the
dispatch inside `open_k9s` is `cfg!(target_os)`-gated.

## Consequences

- k9s opens a terminal window on macOS and Windows with zero configuration.
- First macOS launch may trigger the one-time macOS **Automation (TCC)**
  permission prompt, because `osascript` controls Terminal.app. This is the
  standard mechanism; kindboard is not required to be notarized for it.
- Regression tests pin the argv shapes and the escaping round-trips
  (`macos_default_argv_*`, `windows_quote_*`, `windows_default_argv_*`).
- Behavior on Linux (and any OS with a PATH emulator) is unchanged.
