# ADR-0013 — CLI detach, verbosity and file logging

- **Status:** Accepted
- **Date:** 2026-09-13

## Context

`kindboard` is an eframe/egui desktop binary (`kindboard-app`). Running `./kindboard` from a terminal blocks the shell until the window closes, and there is no way to troubleshoot from the CLI: the only flags are `--version`/`--help` and the `--screenshot*` dev/CI flags; logging is capped at Warn to stderr with no timestamps and no file output.

User requirement: the binary should either background itself after launch, or expose troubleshooting options on the CLI. Tech-lead decision: **both** as explicit opt-in flags; default behavior stays foreground (zero surprise, keeps `--screenshot` CI flows and terminal troubleshooting intact).

## Decision

- **`--detach`** — launch the GUI in the background:
  - The process re-execs itself (`std::env::current_exe`) in a **new session** (`libc::setsid()` via `CommandExt::pre_exec`, Unix-only guard — the app is already Linux/macOS-only), stdio redirected to `/dev/null`.
  - Env guard `KINDBOARD_DETACHED=1` set on the child so it never re-detaches; `--detach` is also stripped from the child argv.
  - Parent prints `kindboard <version> started in background (pid N)` plus the log-file path and exits 0.
  - `--detach` combined with any `--screenshot*` flag is a usage error (exit 2): screenshot mode must exit after capture, and detach would swallow that.
- **`-v` / `--verbose`** (repeatable) — raises the log level: `-v` = Debug, `-vv`/`-vvv` = Trace. Default remains Warn.
- **`--log-file <path>`** — tee all log records to the file too, with timestamps. In `--detach` mode the default log file is `<data_dir>/kindboard/kindboard.log` where `data_dir = dirs::data_dir()` (already a dependency; `~/.local/share` on Linux, `~/Library/Application Support` on macOS — matching the app's persistence root); parent dirs are created recursively.
- **Logger** — a single `AppLogger` implementing `log::Log`, writing `kindboard [HH:MM:SS.mmm] LEVEL: msg` to stderr AND optionally to a `Mutex<File>` (flush per record). No new logging crate.
- **Core instrumentation** so `--verbose` is actually useful: add `log = "0.4"` to `kindboard-core`; `log::debug!` when exec spawns a subprocess (program + args only — never env/secret material; ADR-0009 redaction stays), `log::debug!` on topology watch errors, `log::info!` on provision step transitions and dependency-install start/completion. Bounded, chatty-free.
- **Help text** updated to document all flags. Keep the hand-rolled arg parser (no clap — boring stack); add `libc = "0.2"` to `kindboard-app` for `setsid` only.
- **Unknown args remain ignored** (backward compat with existing behavior).

Alternatives considered (rejected):

- **clap / argh** for parsing — new heavyweight dependencies; the existing hand-rolled parser already covers the small flag surface. Rejected.
- **Auto-background by default** — breaks `--screenshot` CI and terminal troubleshooting. Rejected.
- **Wrapper script / systemd unit / nohup** — not portable to macOS, hides failure modes. Rejected.

## Consequences

- Default foreground behavior is unchanged: `--screenshot` CI flows and terminal troubleshooting keep working.
- macOS is supported (`libc::setsid` exists there).
- One tiny new dep (`libc`) in `kindboard-app`; `log` added to `kindboard-core` (already present in `kindboard-app`).
- Log lines must never contain secrets (kubeconfig tokens, cluster passwords) — house rule from the 2026-09-12 security audit; the exec subprocess debug line logs program + args only and never env.

## Verification

- Unit tests for the arg parser: verbose counting (`-v`→Debug, `-vv`/`-vvv`→Trace), `--log-file` capture, `--detach` conflicting with `--screenshot*` (exit 2), missing values.
- Command-builder test for detach: child argv has `--detach` stripped, env guard `KINDBOARD_DETACHED=1` set, stdio null.
- Manual smoke: `cargo run -p kindboard-app -- --detach -v` prints pid + log path and returns instantly while the window opens; `--screenshot` still captures on Xvfb.
