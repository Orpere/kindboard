# ADR-0008 — Module boundaries: UI-free `kindboard-core`, thin `kindboard-app`

- **Status:** Accepted
- **Date:** 2026-09-12
- **Supersedes:** ADR-0001 (workspace split)

## Context

kindboard must orchestrate subprocesses (kind/docker/kubectl/helm/cilium), edit `~/.kube/config`, and render a live topology. The highest-risk, hardest-to-test code is the orchestration; the UI is immediate-mode egui that should stay dumb. If UI and orchestration are coupled, every bug requires a running desktop session to reproduce.

## Decision

Split into two crates (already agreed in ADR-0001), with a hard rule:

- **`kindboard-core`** is a `#![forbid(unsafe_code)]` library with **zero egui/eframe dependencies**. It owns the tokio runtime, all subprocess spawning, kube-rs, kubeconfig writes, and persistence. It exposes only: typed data (`ClusterSpec`, `TopologyGraph`, `Tool`), a `Command` enum (requests), an `Event` enum (responses), and an `Error` enum. It is unit/integration-tested with `cargo test` on CI — no GUI.
- **`kindboard-app`** is an eframe binary that enqueues `Command`s and renders `Event`s. It contains no business logic, no subprocess spawning, no kubeconfig access. The only seam is `CmdBus`/`EventBus` (crossbeam channels).

Consequences (accepted):

- Core is fully testable headlessly; the app is smoke-tested by launch + a fake `CmdBus`.
- `egui` can be swapped without touching orchestration (future-proofing, not current work).
- Slight ceremony: every new feature needs a `Command` + `Event` pair. This is the point — it forces an explicit contract.
- The UI cannot react faster than the channel round-trip; acceptable (events are infrequent relative to frame time).

Verification: the architecture/contracts docs encode this seam; a lint (CI script) greps `kindboard-app` for `tokio::process`/`kube::` imports and fails if found.
