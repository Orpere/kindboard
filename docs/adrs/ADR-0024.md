# ADR-0024 — Theme-aware logo tint: dark lettering on light themes

- **Status:** Accepted
- **Date:** 2026-09-15

## Context

`icons::logo_image` (tool logos in the Dependencies panel) and
`icons::brand_mark` (top-bar brand mark) painted their embedded PNGs with a
fixed `Color32::WHITE` tint.

User report: **on the Dependencies panel the white logo letters cannot be
seen** — the embedded artwork is mostly white lettering, which disappears on
the Light theme's pale background (`bg 0xf5f7fa`). Measured near-white share
of visible pixels: kind 56% · kindboard brand mark 56% · cilium 49% ·
kubernetes 41.5% · traefik 30%.

Requirement: choose a per-theme color so the letters are visible in **every**
theme.

## Decision

A new palette field `logo_tint` drives the image tint for both the tool logos
and the brand mark:

| theme | `logo_tint` | rationale |
|---|---|---|
| Dark | `WHITE` | dark background — white lettering stays (unchanged) |
| Light | `0x2f3a45` | dark neutral: white artwork reads as dark on pale surfaces |
| HighContrast | `WHITE` | black background — white lettering stays (unchanged) |

Measured contrast (WCAG formula, ITU-R BT.709): **Light ≈ 10.8:1**, and
Dark/HighContrast inherit the historical white-on-dark look. The 3:1
large-glyph minimum is locked by a regression test that asserts the
`logo_tint`/`bg` contrast ratio in every theme.

## Consequences

- Tool logos render as dark monochrome silhouettes on the Light theme
  (brand colors are restored in the dark themes where white is kept). This is
  the deliberate, predictable trade-off of a single multiplicative tint.
- `Palette` gains one field; the reference values are documented in
  theme-contract.md (palette table + §1 API block).
- Regression tests: `logo_tint_contrasts_with_bg_in_every_theme` (≥ 3:1 in
  all themes) and `logo_tint_values_are_stable` (WHITE / `0x2f3a45` / WHITE).
