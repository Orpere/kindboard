# ADR-0028 — Zero paid/usage-based GitHub features: revert CI adoption, local-first pipeline

- **Status:** Accepted
- **Date:** 2026-09-15
- **Supersedes:** [ADR-0027](ADR-0027.md) (in full) — its GitHub Actions + dependabot adoption is reverted. This ADR reinstates the "no GitHub Actions / Makefile-only releases" stance of [ADR-0017](ADR-0017.md).

## Context

On 2026-09-15, ADR-0027 adopted GitHub Actions (`ci.yml`, `security.yml`,
`release.yml`) and dependabot to add always-on quality gates, secret scanning,
dependency review, and signed/attested/SBOM'd releases. That was a defensible
defense-in-depth call for an enterprise-facing tool — but it is now overruled
by repo-owner policy.

The owner's constraint is absolute: **zero GitHub paid/usage-based features,
and no third-party bot accounts.** GitHub Actions compute is usage-metered,
and dependabot acts as a third-party bot with write access to the lockfile —
both are out under that policy. Only GitHub's free, unmetered features remain:
Releases (as a distribution endpoint), Pages, Security Advisories, issue
templates, and CODEOWNERS.

## Decision

1. **Remove all CI/CD automation.** Delete `.github/workflows/*` and
   `.github/dependabot.yml`. No GitHub-hosted compute, no bot accounts.
2. **Run every gate and the release locally.** The Makefile is the single
   pipeline entry point:
   - `make check` — fmt (`cargo fmt --all --check`), clippy (`-D warnings`),
     tests (`cargo test --workspace`)
   - `make audit` — RustSec advisory scan (cargo-audit)
   - `make deny` — license/bans/sources/advisories against `deny.toml`
     (cargo-deny)
   - `make build` — the gates, then release artifacts in `dist/` + `SHA256SUMS`
   - `make check-targets` — cross-compile checks for every supported OS target
   - `make release` — tag + build + `gh release create` (GitHub Releases as the
     distribution endpoint only)
   - `make publish` — deploy `web/` to GitHub Pages via the `gh-pages` branch
3. **Keep GitHub for free features only.** Releases (distribution endpoint),
   Pages, Security Advisories, issue templates, and CODEOWNERS.
4. **Supply-chain evidence becomes local.** SHA256SUMS (verified by installers
   over HTTPS), macOS Developer ID notarization + stapling (when the
   notarization credentials are set), and digest-pinned tool downloads
   (`crates/kindboard-core/src/deps/registry.rs`) remain the proof a consumer
   can check. No cosign, SLSA provenance, or SBOM — those were CI outputs and
   are removed with the workflows.

## Consequences

- **Pros.** Zero GitHub spend and zero third-party bot trust surface; the
  whole pipeline is reproducible on any machine with the toolchains; simpler
  security story (no secrets ever leave the author's machine).
- **Costs.** No remote, always-on validation — a contributor can push without
  gates having run. Mitigation: `make check`, `make audit`, and `make deny`
  are the documented pre-push and pre-release gates, and `make build` runs
  them before producing artifacts. Releases depend on the author's machine
  and its cross toolchains (osxcross for darwin, mingw64-gcc for windows); a
  compromised build host can produce malicious binaries (accepted residual
  risk, recorded in the threat model as T9).
- **Supply-chain evidence is thinner than ADR-0027's.** Consumers can verify
  SHA256SUMS and macOS notarization, but there is no out-of-band signature or
  provenance artifact. Accepted per owner policy.
- **Docs touched.** `README.md`, `SECURITY.md`, `CONTRIBUTING.md`,
  `docs/threat-model.md`, `docs/architecture.md`, `web/index.html`,
  `web/README.md`, and the `Makefile` header.
